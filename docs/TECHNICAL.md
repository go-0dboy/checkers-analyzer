# Техническая документация

## 1. Обзор архитектуры

Приложение построено по слоистой схеме без фреймворков. Каждый модуль —
ES‑модуль с одной зоной ответственности; зависимости направлены строго вниз
по слоям и не образуют циклов.
                ┌───────────────────────────────────────────────────┐
UI-слой         │ main.js (оркестрация, режимы, модалки)            │
                │ themes.js · toast.js · export.js (утилиты)        │
                ├───────────────────────────────────────────────────┤
представл.      │ board.js (отрисовка/ввод) · history.js (нотация)  │
                ├───────────────────────────────────────────────────┤
логика          │ engine.js (правила) · pdn.js (PDN 3.0)            │
                ├───────────────────────────────────────────────────┤
инфраструктура  │ storage.js (файлы/буфер/prefs)                    │
                └───────────────────────────────────────────────────┘


Принцип: `engine.js` и `pdn.js` не знают о DOM; `board.js` не знает правил;
`main.js` не рисует сам и не считает ходы — только маршрутизирует намерения
пользователя и синхронизирует панели.

## 2. Модель данных

### Позиция
Доска — массив длины 64, индекс `i = rank*8 + file`, где `rank 0` = 1‑я
горизонталь. Клетка: `null | 'w' | 'b' | 'W' | 'B'` (строчные — простые,
прописные — дамки). Игра идёт только по тёмным клеткам
(`(file + rank) % 2 === 0`).

### Состояние
`{ board, turn, plies }`. `plies` — счётчик полуходов; `plies % 2 === 0`
соответствует ходу белых. Позиция с очередью чёрных стартует с `plies = 1`,
чтобы нумерация нотации при загрузке FEN была корректной.

### Ход
`{ from, to, path[], captures[], king, isCapture }`. `path` — все клетки пути
(для серий взятий — посадки); `captures` — съеденные в порядке взятия; `king` —
«дамочность» фигуры на финише хода.

### Дерево ходов
`HistoryNode { nid, move, parent, state, children[], commentsBefore[], commentsAfter[] }`.
`children[0]` — магистраль, `children[1..]` — вариации. Комментарии хранятся в
двух фазах, чтобы round‑trip сохранял их позицию относительно хода.

### Теги партии
Объект `gameHeaders` (`Event`, `Site`, `Date`, `Round`, `White`, `Black`,
`Result`, `GameType`, …). Живёт в `main.js`, редактируется паспортом
расстановки и модалкой сохранения.

## 3. Движок правил (`engine.js`)

Реализованы русские шашки:

- простая ходит на 1 по диагонали вперёд; бьёт на 1 вперёд **и назад**;
- дамка «летающая» — ходит и бьёт на любое расстояние по диагонали;
- взятие обязательно; превращение в середине серии действует сразу;
- съеденные снимаются **после** серии (во время серии блокируют проход и
  повторный прыжок через ту же шашку).

### Локальное правило завершения серии
Ключевая нетривиальность. Реализовано в `_explore` двухпроходным циклом по
посадкам за каждой жертвой:

1. для каждой посадки рекурсивно считаются под‑серии;
2. если за жертвой есть хоть одна посадка с продолжением (`hasContinuation`),
   то посадки, обрывающие бой за этой же жертвой, **запрещены**; если
   продолжающих посадок нет — серия честно заканчивается любой длины.

Это **не** «максимальное взятие по длине»: короткая серия легальна, когда за её
жертвой продолжить физически невозможно. Пример: `f8xg7-h6` допустимо при
наличии длинной `f8xd6-c5xb4-a3xb2-c1`, потому что за жертвой на `g7`
продолжения нет; а остановки на `b2/a1` в позиции с жертвой `f6` запрещены,
потому что за `f6` были клетки с продолжением. Именно это свойство держит
этюдные конструкции (треугольник Петрова, петля).

### Окончание партии
Победа — у стороны нет легальных ходов. Ничья — эвристика «ровно две дамки».

### FEN
Кодирование/декодирование по PDN 3.0 §10. Нумерация полей 1..32 по тёмным
клеткам от 8‑й горизонтали к 1‑й. Чтение либеральное: терпит завершающую точку
и слитный цвет секции (`W13,…`), которые ставят реальные файлы.

### Разделитель взятия
По PDN 3.0 §11: типы 25 (русские) и 41 (шпанциретти) пишут `:`, остальные `x`.
Настраивается через `setCaptureSep`/`sepForGameType`; при загрузке берётся из
`GameType`, иначе `:`.

## 4. Парсер и генератор PDN (`pdn.js`)

Следует принципу стандарта §1.2: **чтение либерально, запись строго**.

- Токенизация ловит комментарии `{…}` целиком (PDN 3.0 §4.3).
- Чтение принимает разделители взятия `x`, `:`, `×` (reading grammar §4.4).
- Вариация `( … )` после хода `X` кладётся как **сиблинг** `X` (ребёнок родителя
  `X`), а не как его продолжение — иначе магистраль и ветка менялись бы местами
  при повторной загрузке (баг round‑trip, исправлен).
- Запись соблюдает restrictions §4.2 и переносит строки по ~80 символов.

Соответствие разделам стандарта зафиксировано в комментариях модуля.

## 5. Представление

### `board.js`
Рисует 64 клетки один раз, далее обновляет классы/фигуры по состоянию. Координаты
и порядок клеток учитывают переворот через `_displayToSq`. Ввод — unified
pointer: короткий тап = клик, смещение > 6px = drag. Эмитит `squareclick` и
`dragdrop`. Правил не знает.

### `history.js`
Рендерит нотацию деревом: вариации — блоки `.var-block` с отступом и цветной
вертикальной ветвью по глубине (узел‑точка сверху, хвостик‑окончание снизу).
Номер пары ставится один раз перед ходом белых; `N...` перед чёрным — только
когда последовательность стартует с чёрного хода. Прокрутка к активному ходу —
строго внутри контейнера (никогда не `window`), чтобы страница не уезжала.

## 6. UI‑утилиты

- `themes.js` — пикеры темы (`data-theme`) и скина (`data-board`); запись в
  `localStorage`; глобальное закрытие по клику вне и по Escape.
- `toast.js` — один элемент `#toast`, автоскрытие.
- `export.js` — собирает SVG текущей доски из DOM (честная ориентация и
  координаты) в универсальной классической палитре; чёрные фигуры — со светлым
  ореолом. Палитра универсальна намеренно: файл‑картинка должна читаться на
  любом фоне при шаринге.

## 7. Система оформления

Два ортогональных слоя на корне `<html>`:

- `[data-theme]` — цвета интерфейса (фон, панели, текст, акцент);
- `[data-board]` — доска и фигуры через дизайн‑переменные
  (`--piece-*`, `--sq-*-bg`, `--frame-bg`, `--king-*`).

Любой скин корректен на любой теме. Контраст чёрных фигур на тёмных полях
(фигуры стоят только там) обеспечен светлым ореолом в `box-shadow` и усиленным
верхним бликом — приём работает независимо от фона. Переключение морфит
`border-radius`/`background` за ~0.4s.

## 8. Расширение

- **Новая тема:** добавить блок `[data-theme="…"]` в `style.css`, свотч и кнопку
  в `index.html`, идентификатор в `THEME_IDS` (`themes.js`).
- **Новый скин:** добавить блок `[data-board="…"]` в `style.css`, свотч и кнопку
  в `index.html`, идентификатор в `BOARD_IDS` (`themes.js`).
- **Новое правило:** править только `engine.js`; представление и PDN не трогать.

## 9. Известные ограничения

- Ничья по **трёхкратному повторению** позиции и по **правилу N ходов дамками**
  не реализована (детектор повторов и счётчик «ничейных» полуходов — возможное
  расширение в `engine.js`/`history.js`).
- Экспорт SVG использует классическую палитру, а не цвета активного скина
  (осознанное решение ради читаемости на любом фоне).
- Inline‑setup команды `/FEN"…"/` внутри партии (PDN 3.0 §5.2) не парсятся —
  позиция задаётся тегом `[FEN]` в заголовке.
